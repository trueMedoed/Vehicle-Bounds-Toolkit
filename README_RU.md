# ME Vehicle Bounds Toolkit

Независимый набор инструментов Arma Reforger Workbench для создания bounding boxes отдельных prefab техники и обнаружения изменений между сборками игры.

## Назначение

Toolkit измеряет для каждого поддерживаемого prefab техники **axis-aligned bounding box (AABB)**. Каждый bounding box задаётся минимальной и максимальной точками относительно центра техники. В именах проекта, например `VehicleBounds`, слово `bounds` означает именно этот bounding box.

Toolkit отвечает на два вопроса:

1. Покрывает ли эталонная сцена все включённые prefab техники из поддерживаемых каталогов фракций?
2. Изменился ли bounding box какой-либо техники после обновления игры или изменения сцены?

В коде, именах ресурсов и диагностике для эталонной сцены используется термин `fixture`. **Эталонная сцена** — это контролируемая сцена World Editor, содержащая по одному помеченному root для каждой измеряемой единицы техники.

Toolkit читает faction-specific каталоги `VEHICLE` для `CIV`, `FIA`, `US` и `USSR`. Он проверяет размещённые roots техники, измеряет каждый root вместе с дочерними сущностями и сохраняет детерминированные локальные границы с информацией о фракциях и типах техники.

Полученные данные можно использовать для предпросмотра в редакторе, проверки размещения, расчёта интервалов и регрессионного тестирования.

## Быстрый запуск

1. Откройте `ME_Vehicle_Bounds_Toolkit/addon.gproj` в Workbench.
2. Откройте `Worlds/ME_VBT_VehicleBoundsFixture.ent` в World Editor.
3. Дождитесь загрузки сцены и ресурсов техники.
4. Запустите через `Plugins > ME Vehicle Bounds Toolkit`:
   1. `VBT: Preflight fixture names`
   2. `VBT: Validate fixture coverage`
   3. `VBT: Generate bounds snapshot`
5. Проверьте консоль Workbench или `script.log` на сообщения `[ME_VBT_WB]`.
6. Изучите все различия Candidate/Baseline до принятия нового Baseline.

Переходить в Play mode не требуется. Все команды являются инструментами World Editor.

Подробное описание команд находится в разделе [Плагины Workbench](Docs/PLUGINS_RU.md).

## Snapshots

Каждый snapshot хранит:

- версии схемы, генератора, эталонной сцены и сборки игры;
- канонический путь ресурса prefab;
- локальные минимальную и максимальную точки AABB;
- отсортированные ключи фракций;
- отсортированные labels типов техники.

Записи сортируются по каноническому пути prefab. Имена сериализованных контейнеров создаются из имён файлов prefab, чтобы текстовые diff оставались читаемыми.

### Candidate

`Configs/Generated/ME_VBT_VehicleBoundsPerPrefabCandidate.conf` создаётся из текущей сборки игры и состояния эталонной сцены. Повторный запуск генератора может заменить его содержимое.

Ручные изменения Candidate не должны считаться эталонными.

### Baseline

`Configs/Generated/ME_VBT_VehicleBoundsPerPrefabBaseline.conf` является вручную принятым эталоном. Генератор читает его, но никогда не перезаписывает.

Чтобы принять ожидаемое изменение:

1. создайте Candidate;
2. убедитесь, что сохранение и повторная загрузка Candidate завершились успешно;
3. изучите семантическое сравнение и текстовый diff;
4. убедитесь, что каждый добавленный, удалённый или изменённый prefab является ожидаемым;
5. вручную замените содержимое Baseline проверенным содержимым Candidate;
6. сохраните имя файла Baseline и его существующий `.meta` файл;
7. перезагрузите ресурсы или перезапустите Workbench, если предыдущий Baseline остался в кэше;
8. снова запустите генератор и получите `snapshot_compare status=PASS`;
9. запустите генератор ещё раз, чтобы подтвердить детерминированность результата.

Никогда не копируйте `.meta` файл Candidate поверх `.meta` файла Baseline. Это независимые зарегистрированные ресурсы с разными GUID.

## Значения результатов

- `PASS` — операция завершилась успешно. Для сравнения snapshots это означает семантическую идентичность Candidate и Baseline.
- `DIFF` — Candidate корректен, но отличается от Baseline. Проверьте все изменения до их принятия.
- `FAIL` — Toolkit не смог получить надёжный результат. Используйте значение `reason=...`, чтобы найти проблему сцены, каталога, ресурса или проверки.

Измерение границ после холодной загрузки может выполняться дольше тайм-аута автоматизации Workbench. Сам по себе тайм-аут не означает ошибку — проверяйте итоговые сообщения `[ME_VBT_WB]` в `script.log`.

## Обновление эталонной сцены

Если после обновления игры изменилось покрытие каталогов:

1. найдите в диагностике добавленные или удалённые пути prefab;
2. добавьте или удалите соответствующий root техники в нужном faction layer;
3. укажите точный канонический путь каталога через `ME_VBT_VehicleBoundsFixtureMarkerComponent`;
4. оставьте каждый измеряемый root неповёрнутым;
5. изменяйте ожидаемое количество roots и идентификатор эталонной сцены только при намеренном создании новой версии;
6. выполните предварительную проверку имён и проверку покрытия;
7. создайте и изучите новый Candidate;
8. принимайте новый Baseline только после полного понимания всех различий.

Обязательные данные фракций, manager, scope и каталогов проверяются строго. Отсутствующие данные нужно исправлять, а не скрывать с помощью global catalog fallback.

## Префиксы

- Префикс скриптов и классов: `ME_VBT_`
- Префикс диагностики: `[ME_VBT_WB]`

Ищите диагностический префикс в `script.log`. Основные семейства результатов:

```text
fixture_names
fixture_coverage
snapshot_candidate
snapshot_compare
```
